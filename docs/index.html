what it does

one command per release.

reads the GitHub API or your local checkout, drops the noise, ranks what matters and writes it all down.

notes

Release notes

Conventional Commits grouped into sections. Merges, dependency bumps, typo fixes and duplicates get dropped.

shill next

Next version

Breaking is major, feat is minor, the rest is patch. Prints the commits that decided it.

changelog --write

CHANGELOG.md

Adds a Keep a Changelog section at the top. Run it twice and the file stays the same.

highlights

Top 3 first

Commits scored by type, PR link and files changed. The top three lead every post. First-time contributors get named.

--voice voice.md

Sounds like you

Point it at a few of your old posts and the model copies how you write.

watch

Watch mode

Polls releases and tags every 5 minutes and posts each new release once. State lives in a JSON file.

--local

No API needed

Reads your checkout with git log. Private repos and repos outside GitHub work too.

ui

Dashboard

Every draft previewed the way it will look, with a character ring and a copy button. Runs on 127.0.0.1, never posts.

--post discord

Opt-in posting

Discord and Telegram only go out when you pass a webhook or bot token. X is always drafts only.

github action

runs on every release.

add the Action and publish a release. shill writes the notes into the release body between two markers (anything you wrote stays), drafts every post and puts them in the job summary.

# .github/workflows/release.yml
on:
  release:
    types: [published]
permissions:
  contents: write
jobs:
  shill:
    runs-on: ubuntu-latest
    steps:
      - uses: OWNER/shill@v1
        with:
          channels: x,thread,discord
          post: discord
          discord_webhook: ${{ secrets.DISCORD_WEBHOOK }}

faq

questions people ask.

Do I need an AI key?

No. Without a key shill fills templates from your Conventional Commits. With OPENAI_API_KEY or ANTHROPIC_API_KEY the model writes the prose, and any draft that breaks a channel rule falls back to the template with a warning.

What gets sent to the model?

Commit subjects, scopes, PR numbers, author handles and the version. Never code or diffs.

Will it post to X?

No. X drafts go to files, the dashboard and the job summary. Discord and Telegram only post with explicit flags.

My commits are not Conventional Commits.

They still show up, under Other Changes, and count as a patch bump. Conventional Commits give you better notes.

Does it have dependencies?

Zero runtime dependencies. Node 18 or newer, plus git for local mode.

Is $SHILL part of the tool?

No. The CLI, Action and MCP server are MIT licensed and work without any token. Nothing here is financial advice.
